# Studio audio selection

Svara separates recording selection from audio transport. An audio-only stream
of a cinematic video still contains that video's dialogue, silence, and edits.
YouTube describes an Art Track as the sound recording plus album artwork:
[YouTube Art Tracks](https://support.google.com/youtube/answer/6007071?hl=en).

## Architecture

- `StudioAudioPolicy` is a pure Kotlin domain policy. It rejects explicit music
  video, cinematic, concert, and live-version labels while retaining song names
  such as “Video Games” and “Live and Let Die.” Title filtering is a heuristic.
- `YouTubeBridge` owns provider selection and recording evidence. Every Songs
  query, including mix/album/concert queries, uses `MUSIC_SONGS`. There is no
  fallback to `MUSIC_VIDEOS` or general YouTube video search.
- `YouTubeRepository` owns pagination, caching, cancellation, and the validated
  playback contract. It requests `kind: songs`, uses a new cache namespace, and
  rejects missing recording evidence, video MIME types, or changed recording IDs.
- `SvaraHandler` continues to receive a validated `ResolvedTrack`; local-file
  playback is unaffected. Failed online resolutions leave the queue available.

## Search configuration

The provider configuration is enforced in code rather than a user-toggleable
preference. No new dependency, API key, or `pubspec.yaml` setting is required.

```kotlin
val filter = when (kind) {
    "songs" -> YoutubeSearchQueryHandlerFactory.MUSIC_SONGS
    "artists" -> YoutubeSearchQueryHandlerFactory.MUSIC_ARTISTS
    "albums" -> YoutubeSearchQueryHandlerFactory.MUSIC_ALBUMS
    "radios" -> YoutubeSearchQueryHandlerFactory.MUSIC_PLAYLISTS
    else -> throw IllegalArgumentException("Unknown music search kind")
}
```

The Dart bridge request explicitly includes `kind: songs` on each cursor page.
The search cache prefix is `youtube:studio-songs:v3`, keeping earlier search
results out of this policy's cache. Native continuation identity includes the
search kind and query, so pagination cannot switch catalogs.

## Recording evidence before playback

The native resolver checks the fetched watch-page title against the policy and
accepts one of these evidence paths:

1. The same video ID was recently returned by a Songs-catalog search.
2. The description contains both Art Track markers: “Provided to YouTube by”
   and “Auto-generated by YouTube.” This is metadata evidence, not proof of the
   waveform contents or an authenticated distributor identity.
3. A bounded Songs-catalog lookup for the fetched title/uploader contains the
   **exact same video ID**. The resolver inspects at most 50 results from one
   page and never substitutes a similarly named track.

Evidence is cached in memory for 15 minutes with a maximum of 200 IDs. Saved
`musicCatalogSong` flags, Topic/VEVO channel names, and “Official Audio” titles
alone cannot bypass native validation. Playlists and regional charts may hold
music-video IDs; these fail with `no_studio_audio` when verification fails. The
user can select the album recording through Songs search.

## Audio-only transport

After recording verification, the native resolver chooses only HTTPS
`AudioStream` entries using progressive HTTP and M4A/WebM audio formats. Quality
selection remains bitrate-based, and codec retries use the same recording ID.
There is no fallback to a muxed video stream.

The Dart repository validates the bridge response before giving it to playback:

```dart
if (data['studioAudioVerified'] != true) {
  throw const SourceException(
    'no_studio_audio',
    'A studio audio version could not be verified. '
        'Search for the song in Songs and select its album recording.',
  );
}
if (!{'audio/mp4', 'audio/webm'}.contains(data['mimeType'])) {
  throw const SourceException(
    'unsupported_format',
    'The source did not return a supported audio-only stream.',
  );
}
```

`studioAudioVerified` means the recording-selection policy accepted the source.
It does **not** mean the audio was analyzed for silence, dialogue, or noise.
Songs and Art Tracks can themselves include those sounds, and provider metadata
can be incomplete or incorrect. Absolute content guarantees require a curated
recording catalog or audio-content analysis. Silence removal is deliberately
excluded because it can remove intentional pauses in music.

## Rebuild and verification

Rebuild the Android application: Flutter hot reload alone cannot update the
Kotlin bridge. Both bridge and repository must ship together because old bridge
responses lack the new playback-contract fields.

```sh
flutter analyze
flutter test
cd android
./gradlew :svara_youtube:testDebugUnitTest --offline
```

Tests cover cinematic/live labels, misleading channel/title evidence, original
recording identity, missing native verification, rejected video MIME types,
audio-only codec retries, cancellation, pagination, and existing playback flows.
Live provider behavior still needs an Android smoke test with representative
Songs, old music-video playlists, and regional chart entries.
